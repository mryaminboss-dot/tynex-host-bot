LIMITATION: Heuristic static scanning cannot prove that arbitrary code is safe. Approved user code is still executed with the hosting process account's permissions. Production use should isolate each project in a container/VM with restricted filesystem, network, CPU, memory, and process permissions.

UPLOAD RETENTION UPDATE: Uploaded source files are archived under upload_bots/_user_uploads/<user_id>/ and remain available in Admin Panel -> User Files. Re-uploading a ZIP with the same filename creates a separate project folder and never deletes the previous project. Uploads are auto-approved after the static security scan; they are not auto-started.

RUNNER UPDATE: Python projects use a project-local .venv and install requirements.txt there before launch. Node projects run npm install when package.json exists. Per-project logs are stored at logs/bot_<project_id>.log and are shown in View Logs. Dependency installation requires network access and can fail; inspect logs for the exact package error.
AUTO-START UPDATE: Approved .zip, .py and .js projects are automatically started after static scanning. Python requirements are installed into a project-local .venv; Node package.json dependencies are installed with npm. A running project refreshes to a Stop button instead of showing a misleading Already running popup.
